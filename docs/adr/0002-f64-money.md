# Money as f64/REAL, never rounded, display rounding only

All money and prices are stored and calculated as SQLite `REAL`/`f64`, matching the spreadsheet's arithmetic — parity with its cached values was the migration acceptance criterion. Stored values are never rounded; rounding happens only at display (money 2dp, prices/averages up to 4dp, percentages 3dp).

### Considered options
- Integer cents — rejected: US fees like `1.000009` and fractional shares mean cents aren't the natural unit, and conversion would introduce rounding differences against the sheet.

Do not introduce `Decimal`/cent types or store-time rounding — anything else breaks parity silently.
